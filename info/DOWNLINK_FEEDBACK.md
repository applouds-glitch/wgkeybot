# Восстановление потоков: Android и TURN proxy

Изменение требует обновления Android-клиента и `vk-turn-proxy/server`.
Обновлять можно в любом порядке. Новый сервер со старым клиентом уже
переключает поток после восьми пакетов или одной секунды. Исключение потоков
по данным клиента включается только при поддержке обеими сторонами.

## Поведение

- Клиент использует прежний порог тишины 35 секунд. Один общий обработчик
  сессии проверяет часы раз в секунду и сообщает серверу битовую маску
  готовых потоков, по которым приходили ответы.
- Отчёт передаётся через два исправных потока, если они есть. Изменение
  повторяется через секунду; далее отчёт обновляется на общей сетке keepalive
  раз в 25 секунд. При заполненной очереди обработчик не блокируется.
- Сервер отправляет данные через отмеченные потоки. Проверочные ответы
  возвращаются напрямую через проверяемый поток, даже если он исключён.
  Получение такого ответа позволяет клиенту включить поток обратно.
- Если маска пустая, среди зарегистрированных потоков нет отмеченных или
  последнему принятому отчёту исполнилось 75 секунд, сервер пробует все пути.
- Порядковый номер отчёта общий для UUID сессии. Дубликаты и запоздавшие
  отчёты не меняют маску и не продлевают её срок действия.
- Пороги переподключения клиента (90 секунд) и закрытия молчащего потока
  сервером (180 секунд) сохранены.

## Согласование WGH1

Управляющие сообщения идут внутри уже установленного WRAP, DTLS,
DTLS+WRAP или SRTP транспорта, после обычного 17-байтового заголовка сессии.
Формат WireGuard-пакетов не меняется. `-packet-sequence` по-прежнему должен
быть выключен: это независимый, пока неподдерживаемый клиентом формат.

HELLO — 20-байтовый STUN Binding Indication (`0011`, длина атрибутов 0,
cookie `2112a442`). Поле transaction ID содержит `WGH1`, байт типа сообщения
и случайный 7-байтовый nonce текущего транспортного соединения.
Тип HELLO = 1, ACK = 2, REPORT = 3. Новый сервер возвращает ACK с тем же
nonce. Старый сервер возвращает HELLO без изменений, что не включает функцию.

REPORT имеет длину 64 байта: тот же заголовок с длиной атрибутов 44,
атрибут `0xc001` длиной 40, `uint64` номера отчёта в big endian и 32 байта
маски. Поток `id` соответствует биту `1 << (id % 8)` байта `id / 8`.
Сервер принимает отчёт только после HELLO на данном соединении и при
совпадении nonce. Управляющие сообщения не передаются WireGuard.
`feedback_wire.go` и фиксированный образец в тесте одинаковы в обоих репозиториях.

## Проверки

Сервер: `go test -race ./server` из корня `vk-turn-proxy`.

Клиент: обычные Go-тесты содержат проверки согласования, восстановления,
повторной отправки и пустой маски. Совместные тесты дополнительно запускаются
при заданном `WG_FEEDBACK_SERVER` — абсолютном пути к собранному серверу.
`WG_LEGACY_SERVER` включает проверку со старым закоммиченным сервером.
В `tunnel/tools/libwg-go`: `go test -race -run TestFeedback -v .`
(на macOS нужен тот же overlay для Android TUN API, что и для остальных
нативных тестов проекта).

Тесты используют настоящий код транспортов клиента и отдельный процесс
сервера с локальным UDP echo backend. Потери моделируются отдельно в
направлении сервер → клиент. Часы RX переводятся в интервал тишины
35–90 секунд; это проверка восстановления, а не длительный тест сети VK/VPS.
Покрыты все четыре транспорта, редкие ответы, возвращение исключённого
потока, тишина на всех потоках и совместимость со старым форматом.

## Проверка релизов 1.6.0 и 1.8.1

С сервером `8987ef138814e36e1724560a18469f121b7e83b8` отдельно проверены
исходники релизных тегов, без переноса в них новых транспортных исправлений:

| Клиент | Коммит тега | WRAP / DTLS / DTLS+WRAP / SRTP | Простой 130 секунд |
| --- | --- | --- | --- |
| v1.6.0 | `e83f7313d31e8a5dd2ed4086df8959b50a51bfb4` | Все прошли | Передача возобновилась без переподключения |
| v1.8.1 | `629fb182ed53da546dc87787c1f1ed8ad1fe0b5a` | Все прошли | Передача возобновилась без переподключения |

В каждом режиме использовались два потока. Проверялась точная передача
WireGuard-подобных пакетов типов 1–4 размером 64–1312 байт. Во время простоя
полезные пакеты не отправлялись: соединения поддерживались исходными
keepalive. Для 1.6.0 проверены фоновый режим (25 секунд) и отдельно активный
режим (10 секунд); у 1.8.1 используется общий интервал 25 секунд.
Тесты клиента и серверный процесс запускались с `-race`.

Это локальные тесты сетевого ядра из тегов с UDP echo backend. Для запуска
на macOS использованы заглушки Android JNI/log/TUN; транспортные исходники
и версии зависимостей из тегов сохранены. Запуск APK на Android, Doze,
получение учётных данных VK и реальная сеть VPS этими тестами не покрываются.
На сервере `-packet-sequence` выключен. Клиенты этих версий не отправляют
WGH1-отчёты и продолжают работать через совместимый старый формат.
